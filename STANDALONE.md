# Quaber standalone — Linux x86-64

Архив `quaber.tar.xz` предназначен для сервера без Node.js и npm: runtime встроен в исполняемый файл `quaber`. Нужен Linux x86-64 с glibc и стандартными системными библиотеками (в том числе `libstdc++`); Alpine/musl без совместимого окружения не поддерживается. Для HTTPS должны быть доступны доверенные CA-сертификаты, а часы сервера синхронизированы.

В архиве находятся веб-интерфейс и backend, но по умолчанию **нет исполняемого `kubectl`**: ни `bin/kubectl`, ни `addons/kubectl`. Quaber может запуститься без него, однако вход в кластеры и функции, требующие подключения к Kubernetes, будут недоступны. Для работы с кластерами добавьте в `addons/kubectl` свой совместимый Linux x86-64 исполняемый файл с командами `login` и `proxy`.

## Подготовка пакета

На машине сборки нужны Node.js 22.20+, npm 10+ и зависимости проекта. Сборка:

```sh
npm run build:standalone
```

Результат — `release/quaber.tar.xz`; для сборки и распаковки нужна поддержка `xz`. Рядом создаётся файл `quaber.tar.xz.sha256`. Установленный на машине сборки `kubectl` не включается в архив автоматически.

Если нужно включить свой совместимый `kubectl` в архив уже при сборке, укажите его путь:

```sh
QUABER_LOGIN_KUBECTL=/absolute/path/to/corporate-kubectl npm run build:standalone
```

`QUABER_LOGIN_KUBECTL` указывает на исполняемый файл **на машине сборки**; в этом случае он будет помещён в `addons/kubectl`. По умолчанию удобнее добавить файл после распаковки. Не переносите в архив пароль, kubeconfig или частные CA-файлы без отдельного решения об их защищённом хранении.

Корпоративный клиент должен поддерживать `login URL --username USER --password PASS`, записывать kubeconfig по переменной `KUBECONFIG` и поддерживать команду `proxy` с обычными флагами `kubectl`. Quaber запускает его с отдельными временными `HOME` и `KUBECONFIG` для каждого входа. Поскольку пароль передаётся аргументом процесса, ограничьте локальный доступ к серверу: во время выполнения он может быть виден пользователям, имеющим право читать аргументы чужих процессов. Перед развёртыванием проверьте совместимость клиента на тестовом кластере.

## Первый запуск на сервере

```sh
tar -xJf quaber.tar.xz
cd quaber
umask 077
cp .env.example .env
cp data/bootstrap-user.example.json data/bootstrap-user.json
chmod 700 data
chmod 600 .env data/bootstrap-user.json
```

Для работы с кластерами скопируйте свой Linux x86-64 клиент с командами `login` и `proxy` в распакованный пакет и разрешите его выполнение:

```sh
cp /absolute/path/to/your-kubectl addons/kubectl
chmod 755 addons/kubectl
```

Если клиент ещё не готов, настройку и запуск Quaber можно продолжить без него; Kubernetes-функции станут доступны только после его добавления.

В `.env` заполните `DASHBOARD_MASTER_KEY` постоянным случайным значением длиной не менее 32 символов; лучше использовать 64 случайных шестнадцатеричных символа, полученных на доверенной машине. В `data/bootstrap-user.json` замените пример на свой логин (3–64 символа) и временный пароль (12–256 символов). Не оставляйте значения из примера. После заполнения файлов выполните:

```sh
./check-runtime.sh
```

Проверка охватывает локальные условия запуска; успешный результат не означает успешную авторизацию в кластере.

Запустите сервер от отдельного непривилегированного пользователя, которому доступны каталог приложения и запись в `data`:

```sh
./quaber
```

Адрес для локальной проверки — `http://127.0.0.1:3001`. Backend слушает порт на всех интерфейсах, поэтому не открывайте его напрямую в Интернет: ограничьте доступ межсетевым экраном и используйте HTTPS-реверс-прокси для внешних пользователей. Первичная учётная запись импортируется только при пустой базе пользователей; после успешного импорта файл `data/bootstrap-user.json` удаляется, а при первом входе пользователь должен сменить пароль.

`data` содержит SQLite-базу и зашифрованные kubeconfig. Делайте резервные копии `data` и `.env` с ограниченным доступом. При обновлении остановите Quaber, сохраните `data` и `.env`, замените остальные файлы и запустите снова. **Не меняйте `DASHBOARD_MASTER_KEY` без миграции**: старые сохранённые реквизиты перестанут расшифровываться. Настройка диагностических логов находится в `quaber.config.json`; изменения `.env` и этой конфигурации требуют перезапуска backend.
