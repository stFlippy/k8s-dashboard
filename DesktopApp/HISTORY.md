## Прежний README

# Quaber Desktop

Нативная версия Quaber на Python и Qt. Исходный код и рабочие данные размещены в `DesktopApp`; папка `UserData` создаётся рядом с исполняемым файлом и должна сохраняться при обновлении.

## Запуск из исходников

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

На Windows используйте `.venv\Scripts\python.exe` (в текущем рабочем окружении — `venv\Scripts\python.exe`).
В разделе «Кластеры · Настройки» задаётся **один общий kubectl** для всех
кластеров. Пустое поле означает поиск в PATH; если клиент не найден, приложение
предлагает выбрать файл. Для тестовой обёртки выберите `DesktopApp\Addons\kubectl.exe`.
Старый одинаковый путь из настроек кластеров автоматически переносится в общую
настройку; разные старые пути требуют явного выбора. Пароли остаются индивидуальными.

## Пароль кластера

По умолчанию пароль не сохраняется. Галочка «Сохранить пароль» сохраняет его
только после нажатия «Сохранить», зашифрованным AES-GCM в `UserData/clusters.json`
с существующим ключом `portable.key`. «Проверить» ничего не сохраняет.
При редактировании пароль подставляется скрытым полем; при повторном входе
он подставляется, если у кластеров в группе один и тот же сохранённый пароль.
Если снять галочку и сохранить кластер, сохранённый пароль удаляется.
Полный доступ к `UserData` вместе с ключом даёт доступ и к сохранённым паролям.

## Сборка Windows portable

Собирать следует на Windows x86-64 с доступом к Python и зависимостям:

```powershell
python -m pip install -r requirements.txt
.\build_windows.ps1
```

Распространяется вся папка `build-artifacts\Quaber`. Для обновления скопируйте новые программные файлы в папку пользователя, сохранив её `UserData` и `addons`. Не запускайте рабочую копию из `build-artifacts`: повторная сборка заменяет эту папку. `kubectl` в поставку приложения не включается.

## Статус реализации

Сейчас реализованы локальное хранилище, подключение через корпоративный `kubectl login` и `proxy`, базовая матрица, чтение Pod/Deployment/ConfigMap/ResourceQuota, логи, события, метрики из Metrics API с fallback на kubelet и cAdvisor, консоль Pod, редактирование YAML и операции масштабирования, restart и удаления Pod. Работа над точным переносом всех элементов интерфейса и Windows-приёмкой продолжается.

Файл `UserData/portable.key` переносится вместе с зашифрованным kubeconfig. Полный доступ к `UserData` даёт доступ к действующим подключениям.

## Исправление зависания проверки на Windows

Зависание воспроизводилось при завершении проверки через обёртку: завершался
её процесс, но дочерний `kubectl proxy` оставался запущенным и удерживал
stdout/stderr. Закрытие буферизированного канала ждало поток чтения без ограничения.
Теперь процессы приложения помещаются в Windows Job Object; остановка и таймаут
завершают всё дерево, а ожидание потоков чтения ограничено. На POSIX используется
отдельная группа процессов. Результаты фоновых задач обрабатываются слотами
QObject в GUI-потоке через queued connections. Регрессионные тесты проверяют
реальную Windows-обёртку, таймаут с дочерним процессом и отзывчивость Qt.

## Перенос веб-интерфейса

Добавлены отдельные цветные Pod в матрице, вертикальные заголовки Namespace,
прямые переходы и контекстное меню Pod, цвет вкладок, отдельные фильтры ресурсов,
боковые панели Pod/Deployment, таблицы событий и контейнеров, редактор с нумерацией
строк и поиском, автообновление логов и выбор tail, представление квот с полосами
использования и переключение процентов/фактических метрик. Первоначальная палитра и верхняя
навигация ориентировались на App.css; текущий макет описан ниже. Загрузка namespaces ограниченно параллельная;
при частичных ошибках сохраняются ранее прочитанные данные. Приёмка на одинаковом
наборе реальных кластеров с веб-версией ещё требуется; автоматические тесты не
являются подтверждением полного визуального совпадения.

## Автоматическое восстановление авторизации

При запуске, периодической проверке срока токена и ответе API 401 приложение
автоматически выполняет login, если пароль сохранён. Для каждого кластера
одновременно выполняется одна попытка. Исходный API-запрос повторяется не более
одного раза после обновления kubeconfig. Ответ 403 RBAC не вызывает повторного входа.
Если пароль отсутствует, повреждён или отклонён сервером, открывается форма ввода.
После неудачного автоматического входа новые попытки с теми же данными блокируются;
изменение учётных данных или общего пути kubectl позволяет повторить попытку.
Отмена формы не приводит к повторному открытию при каждом обновлении матрицы.

Визуальные уточнения: три компактные полосы управления матрицей, счётчики статусов,
подсветка строки/колонки, центрированные Pod 15px, индивидуальные подсказки,
разделители кластеров, заголовки 160px как в веб-версии. В боковых панелях добавлены
контекст ресурса, затемнение фона и порядок вкладок Pod по веб-эталону.


## Макет рабочего пространства (11.11.2026)

Основная навигация перенесена в левую панель: Pod list, Квоты ресурсов,
ConfigMaps. Внизу панели находятся настройки кластеров и приложения; выбор темы расположен внутри настроек.
Ширина боковой панели регулируется разделителем и сохраняется.

Темы Dark Modern и Light Modern используют палитру официальных тем VS Code:
https://github.com/microsoft/vscode/tree/main/extensions/theme-defaults/themes
На Windows интерфейс использует Segoe UI (13 px), редакторы и журнал — Consolas
(14 px), как в настройках VS Code для Windows. Выбор темы сохраняется.

Снизу расположен изменяемый по высоте журнал приложения. Кнопка «—» скрывает
его, Ctrl+J или кнопка «Журнал» в строке состояния открывает и скрывает панель.
Доступны автопрокрутка, копирование, экспорт и очистка видимой истории
(до 5000 строк). Файловый журнал сохраняется независимо от видимости панели:
`UserData/logs/quaber.log`, ротация по 2 МБ, до трёх архивных файлов.
Очистка панели не удаляет файл. При запуске через main.py сообщения также
выводятся в консоль IDE. В журнал пишутся операции, длительность и ошибки;
пароли и токены маскируются перед выводом и записью.

Перед изменением макета создан снимок:
`_rollback/20261111-132543-before-ide-layout/DesktopApp.zip`.
В него включены исходники, Addons, UserData с ключом и внешний kubectl;
окружение зафиксировано в requirements.freeze.txt. Проверка целостности
и откат описаны в `RESTORE.md` рядом с архивом. По умолчанию откат сохраняет
действующие UserData; `--with-user-data` восстанавливает данные из снимка.
Механизм проверен на отдельной тестовой копии в обоих режимах.


## Уточнения интерфейса (11.11.2026, после макета IDE)

- Меню цвета вкладки показывает цветные образцы с названиями и отметкой
  текущего выбора. Выбор окрашивает саму вкладку и всю область матрицы,
  включая заголовки и фон вне заполненных ячеек. «Без цвета» возвращает фон темы.
- Тема выбирается в «Кластеры · Настройки» → «Цветовая тема».
- Обычные таблицы кластеров, ConfigMaps, Pods Deployment, событий, контейнеров
  и метрик заменены плоскими QTreeWidget-списками ResourceList. Выделяется вся
  строка, редактирование ячеек отключено; сохранены двойной щелчок и идентификаторы
  ресурсов. Матрица Pod остаётся отдельным специализированным виджетом.
- Квоты представлены карточками с общими колонками: ресурс, использовано,
  лимит, полоса и процент. Числа расположены вне полос; превышение показывается
  реальным процентом, а полоса ограничена 100%. Нерасчётные значения показаны «—».

# Перенос Quaber Desktop на Windows и продолжение работы

## Изменения по запросу пользователя от 2026-11-11

- Пароль кластера разрешено сохранять по галочке, зашифрованным существующим
  переносимым ключом. По умолчанию сохранение отключено. Снятие галочки с
  сохранением удаляет пароль; подробности в `README.md`.
- Путь к kubectl теперь один общий для приложения; пустое поле означает
  поиск в PATH, отсутствие клиента вызывает ручной выбор файла.
- Исправлено зависание при закрытии дочернего proxy, запускаемого через обёртку:
  приложение завершает дерево процессов целиком и возвращает результаты задач
  в GUI-поток Qt. В тестах используются изолированные данные, не рабочая UserData.

Эти изменения уточняют прежние требования о несохранении пароля и поиске в addons.

## 1. Передать проект через Git

Текущая рабочая копия содержит много изменений вне `DesktopApp`. Для переноса именно десктопной версии включите в коммит только её:

```bash
git add DesktopApp
git diff --cached --stat
git commit -m "Start native Quaber desktop application"
git push
```

После `git pull` на Windows откройте в PyCharm папку `DesktopApp` как отдельный проект. История этого чата через Git не передаётся. Файл `WINDOWS_HANDOFF.md` содержит контекст, который можно дать новому чату.

## 2. Запуск в PyCharm на Windows

1. Установите Python 3.12 x86-64 и создайте для проекта виртуальное окружение через **Settings → Project → Python Interpreter**.
2. В терминале PyCharm из папки `DesktopApp` выполните `python -m pip install -r requirements.txt`.
3. Поместите корпоративный `kubectl.exe` в `DesktopApp\addons\kubectl.exe` или добавьте каталог с ним в `PATH`. Это должен быть клиент, поддерживающий `login URL --username USER --password PASS` и стандартные `proxy`/`exec`.
4. Создайте конфигурацию **Python**, укажите `Script path: DesktopApp\main.py`, `Working directory: DesktopApp`, интерпретатор проекта. Запустите.
5. Добавьте тестовый кластер через «Кластеры · Настройки». Пароль вводится только в локальное окно приложения. Проверяйте тестовое подключение до сохранения.

`UserData` будет создана рядом с `main.py`. Не добавляйте её в Git и не передавайте другим людям: вместе с `portable.key` она даёт доступ к действующим kubeconfig.

## 3. Проверки на Windows

Из терминала PyCharm:

```powershell
python -m unittest discover -s tests -v
python -m compileall -q .
```

Проверьте запуск окна и тестовое подключение. Затем проверьте матрицу, фильтры и вкладки, панели Pod/Deployment, логи, консоль, YAML, ConfigMaps и квоты. Изменяющие операции выполняйте только на согласованном тестовом кластере: scale, restart Deployment, изменение ресурсов/YAML/ConfigMap, restart и удаление Pod. Проверьте восстановление подключения после перезапуска, истечение токена и перенос всей папки `UserData` на вторую машину.

## 4. Portable-сборка

Из терминала PyCharm на Windows:

```powershell
.\build_windows.ps1
```

Скопируйте папку `build-artifacts\Quaber` в отдельное место и запустите `Quaber.exe`. Python, Node.js и браузер для этого запуска не требуются. Скопируйте `kubectl.exe` в `addons` рядом с ним или обеспечьте его через `PATH`. При повторной сборке `build-artifacts` заменяется; рабочую `UserData` храните в отдельной portable-папке и переносите её при обновлении.

## 5. Контекст для следующего чата

Скопируйте в новый чат на Windows:

> Продолжи разработку Quaber Desktop по `DESKTOP_TZ.md`. Прочитай `DesktopApp/WINDOWS_HANDOFF.md`, `DesktopApp/README.md` и код `DesktopApp/quaber`. Не изменяй файлы веб-версии без необходимости. Сначала установи зависимости, запусти тесты и приложение из PyCharm, исправь найденные ошибки. Затем доведи функции и визуальное соответствие до критериев приёмки ТЗ, собери portable Windows и проверь его на тестовом кластере. Не проси пароль в чат. В рабочем дереве могут быть чужие незакоммиченные изменения; не перезаписывай их.

## 6. Реализовано и что ещё проверять

Сейчас есть переносимое хранилище с AES-GCM, запуск корпоративного `kubectl login` и `proxy`, базовая матрица с вкладками и импортом/экспортом, чтение основных ресурсов, YAML, логи, консоль через `kubectl exec`, подтверждения, аудит, scale/restart/delete. Backend проверен `unittest`, включая локальный mock `kubectl` и proxy.

До приёмки остаются: запуск самого Qt-интерфейса на Windows, доводка визуального соответствия веб-версии, проверка метрик и графиков на реальном кластере, тонкости поведения матрицы и панели ресурсов, проверка группового повторного входа и реального корпоративного клиента. В этой Linux-среде PyQt6 и `pip` отсутствуют, Windows-сборка здесь не запускалась. Список открыт честно: текущая версия — прототип, а не принятый выпуск.

## Миграция на PyQt5 — 17.11.2026

DesktopApp переведён с PyQt6 на зафиксированный стек CPython 3.11 x64,
PyQt5 5.15.9, Qt runtime 5.15.2 и PyQt5-sip 12.18.0. Импорты, QAction,
mouse coordinates, `exec_()`, QFontDatabase и High DPI адаптированы без
изменения Kubernetes/backend, UserData, формата секретов и safety-проверок.
Preflight подтвердил, что scoped enum из исходного кода поддерживаются данным
PyQt5, поэтому они сохранены без необязательной массовой замены.

Baseline Qt6: 265 тестов за 97.248 с, 1 Windows/POSIX skip. Результат Qt5:
265 тестов за 97.015 с, тот же skip, failures отсутствуют. Compileall,
smoke-импорт 43 модулей, pip check, target API preflight и release environment
check прошли. Офлайн-wheelhouse установлен в третье чистое окружение с
`--no-index --only-binary=:all:`; старый архив сохранён в
`offline-deps/qt6-rollback`, новый архив и SHA-256 manifest созданы.

Отдельный pip-audit 2.10.1 сохранил `dependency-audit.json` и сообщил 30 записей:
7 для runtime cryptography 46.0.7, 14 для build-tool pip 23.2.1 и 9 для
build-tool setuptools 65.5.0. Lock не изменён вне заданной матрицы; перед выпуском
нужно принять риск либо согласовать отдельное обновление зависимостей. Аудит
нативных Qt DLL этим результатом не заменяется.

Portable `build-artifacts-qt5/Quaber` собран с Qt5Core/Gui/Widgets/Svg 5.15.2,
qwindows, SVG/JPEG imageformats, SBOM и release manifest; Qt6-файлов нет.
Интерактивный native smoke окна и полная матрица DPI 100/125/150/200%, два
монитора и 60-минутный soak остаются ручной приёмкой. Production-кластер,
Addons и пользовательская UserData при миграции не использовались и не менялись.
