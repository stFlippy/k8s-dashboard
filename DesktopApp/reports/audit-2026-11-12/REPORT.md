**Как должен выглядеть основной рабочий сценарий**

В постоянной верхней панели: «Назад» → текущая область → статус подключения/данных → **«Только просмотр»** → помощь по клавишам. Панель доступна и над карточкой Pod. Выбранная цель карточки остаётся неизменяемой и заметной; управляющие селекторы должны визуально отличаться от подписей фактической цели.

Начинающий оператор открывает «Приложения (Deployment)» или «Pod», выбирает кластер и пространство имён, видит понятное состояние, а рядом — доступное следующее действие: «Открыть логи», «Почему не запускается?», «События». Успех изменения отображается отдельно от готовности приложения. При ошибке показываются причина, затронутая цель и действие «Повторить чтение», а не только техническая строка внизу окна.

При первом подключении достаточно краткой встроенной справки: **Кластер — окружение; Namespace — область внутри кластера; Deployment — шаблон и число копий приложения; Pod — запущенный экземпляр; контейнер — процесс/часть Pod**. Это рабочие упрощения для навигации, не замена полной модели Kubernetes. Термины Pod/Deployment сохраняются, чтобы пользователь мог сопоставить экран с документацией и сообщением коллеги.

**ПКМ: конкретное поведение, включая удаление Pod из Deployment**

В таблице Deployment → Pod добавить меню:

1. «Открыть Pod»; «Логи»; «Логи предыдущего запуска»; «События»; «Команда в контейнере».
2. «Скопировать имя», «Скопировать IP», «Скопировать путь: кластер / namespace / Pod».
3. «Удалить Pod…» отдельной последней группой. Для управляемого Pod подпись/подсказка объясняет проверку бюджета доступности. При read-only действие заблокировано, рядом доступно «Разрешить изменения…».

«Дропнуть Pod» — понятный рабочий сценарий, но действие нельзя называть гарантированным «Перезапуском»: удаляется текущий объект, а создание и готовность замены зависят от контроллера, квот и других условий. Для управляемого Pod сохраняется **Eviction**, прямой DELETE после отказа не выполняется. PDB ограничивает допустимое нарушение доступности, но не обещает отсутствие простоя; см. [Kubernetes: Disruption Budget](https://kubernetes.io/docs/tasks/run-application/configure-pdb/).

Диалог: **«Удалить Pod application-123?»**; ниже кластер/namespace/владелец; «Текущий экземпляр будет остановлен. Контроллер может создать замену. Локальные данные контейнера могут быть потеряны». Кнопки **«Отмена»** и **«Удалить Pod»**. Для standalone/singleton/системной области — усиленная проверка цели. После принятия запроса показывать «Удаление запрошено», затем обновлять список; не писать «Pod перезапущен».

Меню фиксирует name + UID + cluster + namespace **в момент открытия**. Фоновый refresh не должен подменить цель по текущему номеру строки. Перед действием — свежая проверка UID/владельца и серверный precondition. На двойной клик/повторное нажатие второй запрос не отправлять. Массовое удаление пока не добавлять.

| Другие места | Меню |
|---|---|
| Квадрат Pod в матрице | То же меню, без отличающегося механизма удаления |
| «Все Pod» | То же меню, плюс переход к владельцу при поддерживаемом типе |
| Имя/ячейка Deployment | Открыть, Pod, события, изменить число копий, CPU/память, перезапустить все Pod, копировать имя |
| Пустая проблемная ячейка | Почему нет Pod, события Deployment, показать скрытые фильтром объекты |
| ConfigMap | Открыть, YAML, копировать имя/путь, найти потребителей; запись только через общий action |
| Namespace/кластер | Показать только эту область, добавить/исключить из вида, квоты, копировать имя |
| Вкладка вида | Дублировать, переименовать, цвет, экспортировать этот вид, сбросить размеры, удалить с восстановлением |
| Событие/строка журнала | Копировать сообщение/время/объект; открыть связанный объект |
| Подключение | Проверить, изменить, включить/отключить сбор, экспорт профиля, удалить локальную запись |

Для всех важных меню нужна видимая альтернатива «Действия ▾» и Shift+F10. ПКМ ускоряет работу опытного пользователя, но не должен быть единственным способом найти функцию.

**Логи: разметка и поведение**

Сейчас четыре строки управляющих элементов занимают существенную часть карточки; чекбокс «Последние доступные логи…» меняет смысл поля количества строк, а место пользователя теряется при полном обновлении. Предлагается такая компоновка:

```text
Логи   PROD / payments / api-7d9 / app          [Обновить] [Сохранить…]
Контейнер [app ▾]  Запуск [Текущий ▾]  Строк [1000 ▾]  [Расширенный фрагмент]
[✓ Получать новые] [✓ Следовать за концом] [  Перенос строк]
[Найти в загруженном фрагменте…                  ]  2/8  [↑] [↓]
────────────────────────────────────────────────────────────────────────────
12:40:03.214  INFO   Запрос обработан
12:40:05.802  ERROR  Подключение к базе недоступно
────────────────────────────────────────────────────────────────────────────
Обновлено 12:40:08 · 1000 строк · 180 КиБ · показан ограниченный фрагмент
```

На узком окне панели переносятся или прокручиваются; поле лога занимает всё оставшееся пространство. Моноширинный шрифт 13–14 px; цвета INFO/WARN/ERROR умеренные, не окрашивать всю поверхность. Время компактное, полная исходная метка доступна при копировании. JSON по умолчанию показывать как исходный текст; раскрытие отдельной записи — дополнительный режим. Не интерпретировать HTML или управляющие команды терминала.

- **Получение и слежение раздельны.** Колесо мыши, выбор текста и поиск выключают только следование. Показать «Есть новые строки · К концу». Отключение получения — явная пауза.
- **Контейнер/запуск входят в идентичность фрагмента.** При переключении — «Загрузка логов app / предыдущий запуск…»; старый текст не отображается как новый. Запоздалые ответы игнорируются по generation. Ошибка старого запроса также не должна перекрывать более новый выбор.
- **Поиск:** буквальный текст по умолчанию; поле со счётчиком, Enter/F3 вперёд, Shift+Enter/Shift+F3 назад, переход по кругу. Поиск не фильтрует и не теряет исходные строки. При отсутствии совпадений «Совпадений нет», без модального окна.
- **Честное обновление:** если ответ не изменился, не заменять документ. При изменении сохранять позицию/выделение или приостановить применение нового снимка до «К концу». Polling возвращает ограниченный хвост, поэтому нельзя вслепую дописывать его: будут дубли. Streaming — только если это поддержит существующий канал; замена транспорта не требуется для базового удобства.
- **Ошибки:** «Нет прав читать логи» / «Контейнер ещё не запускался» / «Предыдущий запуск недоступен» / «Не удалось обновить; показан фрагмент от 12:40». Кнопка «Повторить». Пустой ответ — «В этом фрагменте записей нет», а не ошибка.
- **Экспорт:** «Сохранить показанный фрагмент…», имя файла содержит Pod, контейнер, current/previous и время. Показать объём и источник. Это не вся история сервера. Копировать выделенное — обычный Ctrl+C. По умолчанию не создавать архивы с конфигурацией/учётными данными.
- **Масштаб:** QPlainTextEdit, лимит символов/строк, debounce поиска. Qt рекомендует ограниченный plain-text документ для просмотра больших логов: [QPlainTextEdit](https://doc.qt.io/qt-6/qplaintextedit.html).

«Предыдущий запуск» означает предыдущий экземпляр **контейнера в этом Pod**, не старый удалённый Pod и не архив за произвольный период. Это ограничение стоит объяснять одной подсказкой. Для полной истории нужен доступный источник централизованных логов. См. [Kubernetes Logging Architecture](https://kubernetes.io/docs/concepts/cluster-administration/logging/).

**Обмен настройками кластеров: отдельный переносимый профиль**

Текущая модель подключения требует успешного login (`storage.py:208`). Поэтому безопасный импорт без токена нельзя реализовать простым копированием записей `clusters.json`. Нужна отдельная сущность **профиль подключения**, из которой текущая штатная форма входа создаёт личное рабочее подключение. Протокол авторизации остаётся прежним.

Предлагаемый формат `.quaber.json` — JSON с явной версией и allowlist. Пример для обсуждения реализации:

```json
{
  "format": "quaber-workspace",
  "version": 1,
  "profiles": [
    {
      "ref": "payments-prod",
      "name": "Payments PROD",
      "server": "https://k8s.example.invalid:6443",
      "environment": "production",
      "defaultNamespace": "payments"
    }
  ],
  "views": [
    {
      "name": "Payments",
      "profileRefs": ["payments-prod"],
      "namespaces": ["payments"],
      "deployments": ["api", "worker"]
    }
  ]
}
```

| Передавать по явному выбору | Никогда не передавать в командном профиле |
|---|---|
| Название, endpoint, метка среды, default namespace, выбранные виды/фильтры | Пароли, токены, kubeconfig, encryptedPassword/encryptedKubeconfig, portable.key, DPAPI blobs |
| Несекретные теги и отображение | Путь к исполняемому файлу, shell/exec-команды, плагины, произвольные переменные окружения |
| По желанию рекомендации по namespace | Разрешение записи, разблокировка exec, активные операции, журналы и история команд |
| Внутренние ref внутри файла | Локальные UUID как требование существования у получателя; личный username по умолчанию |

Даже такой файл может раскрывать внутренние адреса и имена сервисов: перед сохранением показывать список включённых полей и «Пароли и токены не входят». Не обещать, что файл вообще не содержит чувствительных организационных сведений.

**Экспорт:** «Поделиться настройками…» → выбрать профили → выбрать виды → preview полей/количества → сохранить один JSON. Только выбранные профили, а не все подключения. «Экспорт вида» может предлагать включить минимальные профили, нужные для его сопоставления. Файл не выполняет код и не подключает получателя автоматически.

**Импорт:** ограниченное чтение файла → проверка схемы/версии/размера → таблица «Профиль / endpoint / найденное локальное подключение / действие» → подтверждение → атомарное сохранение профилей/видов. Значения по умолчанию: совпадающее безопасно пропустить; новый создать как **«Не подключён»**. Совпадение по имени не является совпадением кластера. Разные имена с одинаковым endpoint предлагать сопоставить, но не перезаписывать личную учётную запись. Изменение endpoint существующей записи — отдельное явное действие, без переноса старого токена.

Затем «Подключить» открывает обычную форму, пользователь вводит собственное имя/пароль; до этого нет фонового login, обращения к endpoint, загрузки CA или запуска файла из импорта. Для видов ref преобразуется в **новые локальные идентификаторы** после сопоставления. Повторный импорт идемпотентен по выбранному решению, а одинаковые имена видов предлагают «Пропустить / Импортировать копию».

Проверять: максимум 1 МиБ, 100 профилей/видов, длины полей/списков, отсутствие control/NUL, URL без credentials/query/fragment; неизвестные поля новой версии отклонять с понятным сообщением, не silently включать полномочия. Не импортировать ZIP, относительные пути и произвольный kubeconfig под видом профиля. Нужны тесты на запрещённые secret-поля, дубликаты, чужой локальный UUID, неверную версию и отмену/сбой до commit.

Резервная копия личных подключений — отдельная задача с другим контрактом и защитой. Её нельзя смешивать с кнопкой «Поделиться настройками».

**Предотвратить проблемы заранее**

- Любое действие сначала объясняет область и доступность, затем принимает ввод. Не спрашивать подтверждение операции, которую заведомо запрещает read-only.
- Под нагрузкой показывать «Обновляется…», время последнего успеха и частичность. Не выдавать пустую таблицу после 403 за отсутствие ресурсов.
- Если лимит не задан, показывать фактическое потребление CPU/RAM и «без limit», а не только прочерк.
- Бюджет доступности/PDB, HPA и квоты — простые статусы «Проверено / Ограничивает действие / Не удалось проверить»; отсутствие прав не трактовать как отсутствие ограничений.
- Предыдущие логи доступны только при наличии предыдущего запуска; у завершённого init контейнера объяснить, почему нельзя выполнять команду. Список «Контейнеры» тоже должен включать init/ephemeral: сейчас выбор логов расширен, таблица контейнеров ещё нет.
- Операции с конфигурациями показывают diff и затронутые потребители. Несохранённый draft не исчезает из-за scale/restart.
- Временная ошибка обновления не сбрасывает выбранную строку, поиск и положение пользователя; ошибку можно повторить без повторения записи.
- В матрице показывать название кластера без tooltip. Статусы должны различаться текстом/формой, а не только красным и зелёным квадратом.

**Очередность внедрения**

1. Общий режим записи вне настроек, единый action «Назад», клавиши, сохранение команды при read-only.
2. Единое меню Pod в Deployment/списке/матрице с безопасным удалением и копированием; одинаковые проверки из любого места.
3. Логи: поиск, независимые получение/слежение, source identity, ручной refresh, wrap, экспорт и понятные ошибки.
4. Имена/подсказки, доступность кнопок, сохранение draft при других операциях, согласованность состояния карточки.
5. Профили подключения и импорт с preview/mapping; не смешивать с зашифрованной рабочей записью.
6. Model/view матрицы, инкрементальное обновление и расширение диагностики Nodes/Services/Storage из прошлого отчёта.

Приёмка первого этапа: выделить Pod в Deployment → ПКМ → удалить → увидеть правильную цель и отсутствие запроса при read-only; открыть логи → поиск ERROR действительно находит ERROR → прокрутка не выключает получение → Mouse Back возвращает в Deployment; Ctrl+Shift+L блокирует запись, введённая команда остаётся. Проверить смену контекста во время запроса, отказ PDB без DELETE, неизвестный результат, несохранённый YAML, пустые данные, длинные имена и маленькое окно.

**Что остаётся следующим этапом**

- Перенос профилей кластеров: формат, preview и сопоставление подробно описаны выше; реализации пока нет. Нынешний импорт по-прежнему переносит виды и требует локальные кластеры. Названия кнопок теперь предупреждают об области функции.
- Быстродействие большой матрицы: исходные замеры 20–40 тысяч Pod остаются основанием для переработки model/view. Ускорение в этом этапе не заявляется; алгоритм полного построения матрицы не заменён.
- Меню ещё можно расширить копированием IP, предыдущими логами, переходом к владельцу, действиями по namespace/кластеру, потребителями ConfigMap и строками событий. В меню Deployment уже есть переходы к Pod/событиям/YAML; операции изменения доступны из карточки.
- Полная локализация состояний, сортировка списков, отдельный счётчик проблем Deployment, мастер диагностики «Почему не запускается?», выделение уровней/раскрытие JSON в логах и предметные подтверждения остальных операций остаются предложениями. Арифметическое подтверждение убрано из нового сценария удаления Pod, но сохраняется в прочих старых операциях.
- Дополнительная приёмка: production-подобный тестовый кластер, PDB/квоты/HPA, длительное наблюдение памяти, DPI 125–200%, клавиатурная доступность всех диалогов и очень длинные имена. Нужна до распространения сборки операторам.
