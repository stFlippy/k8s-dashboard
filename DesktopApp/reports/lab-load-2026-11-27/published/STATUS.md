# Лабораторная нагрузка: состояние выполнения

Реальные нагрузочные измерения lab1 пока не выполнены. Сохранённый токен
Quaber и токен стандартного kubeconfig истекли. Первая проверка API получила
HTTP 401; последующие короткие проверки также встретили сетевой таймаут.
Для продолжения нужен обычный успешный вход в lab1. Пароли и kubeconfig
в отчёт и репозиторий не включены. Реальные тестовые namespace не создавались.

Подготовлен протокол: 200 Pod, 10 namespace × 5 Deployment × 4 Pod;
1, 3, …, 25 потоков; 2, 4, 6, 8, 10 запросов/с; kubectl proxy и HTTPS;
два повтора (260 загрузок). Во втором повторе порядок потоков обратный.
Лимитер сохраняет состояние между обновлениями; фиксируются заданная и
достигнутая частота, полное время матрицы, ожидание допуска и HTTP-ответ.
Интенсивность нагрузки API сама по себе не означает насыщение кластера.
CPU/RAM stress-контейнеры не запускаются.

Измеритель и генератор графиков проверены на отдельно помеченном локальном
синтетическом стенде. Эти результаты не публикуются как измерения lab1.
Фактическое время ответа лабораторного API при разных QPS до получения
действующего доступа неизвестно; прогнозные числа за измерения не выдаются.

В инструментах отладки Quaber добавлена сохраняемая настройка частоты
1–100 запросов/с на кластер, по умолчанию 2. Стартовый запас — 2 запроса.
Она применяется к RequestPolicy и EndpointBudget и независима от числа потоков.

Проверки проекта: 590 тестов, 588 успешны, 2 пропущены (POSIX mock kubectl
на Windows и недоступная привилегия создания symlink); ошибок и исключений
Qt нет. Отдельно проверены сохранение настройки, оба уровня лимитера,
исключение ожидания допуска из HTTP-времени и UID-границы удаления стенда.
После усиления обработки потерянного ответа создания повторно прошли
три специализированные проверки измерителя и очистки.

Команды запуска и условия: [benchmarks/README.md](../../../benchmarks/README.md).
После восстановления доступа данные и графики можно сохранить в
`published/measured/` с помощью `lab_load.py` и `plot_lab_load.py`.

Для GitHub push требуется восстановить аутентификацию: HTTPS credential
helper не предоставил учётные данные, оба существующих SSH-ключа отвергнуты.
Все изменения исходников готовятся одним локальным коммитом; сборки,
окружения, UserData и временные журналы исключены из индекса.
