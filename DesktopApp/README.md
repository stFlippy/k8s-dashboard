# Quaber Desktop

Локальное приложение PyQt6 для просмотра и управления Kubernetes через внешний
корпоративный клиент. Текущая доработка замечаний и остаточные риски — [review.md](reports/review.md).
Исторические записи отделены в [HISTORY.md](HISTORY.md).

## Запуск

Windows x64, Python 3.11. Для проверенного набора зависимостей:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.lock
.\venv\Scripts\python.exe main.py
```

Внешний kubectl один для всех кластеров; путь задаётся в «Кластеры · Настройки»,
пустое значение использует существующий поиск в PATH. Addons — отладочный
имитатор, его безопасность не является подтверждением production-клиента.
Протокол login/exec, аргументы запуска, TLS и устройство proxy этой доработкой
не менялись. Ограничено чтение HTTP-ответа в проверке подключения.
Открытые вопросы транспорта отмечены непосредственно в review.md.

## Интерфейс и операции

Разделы слева: Нагрузки и Pod, Квоты ресурсов, ConfigMaps, Все Pod, Журнал.
Темы Dark Modern / Light Modern находятся в настройках. Ctrl+J открывает раздел
журнала; это отдельная страница, не нижняя dock-панель. В памяти журнала —
1000 блоков; файл `UserData/logs/quaber.log` ротируется по 2 МБ, 3 архивных файла.
При запуске main.py журнал также поступает в консоль IDE.

По умолчанию отмечен «Только просмотр» внизу слева. Для YAML, масштабирования,
rollout, eviction/delete и exec снимите галочку и решите математический пример.
При разрешённых изменениях боковая панель алая. При смене представления/раздела
или через 60 секунд без действий включается просмотр. Повторная установка галочки
блокирует новые операции без подтверждения. Разрешение расходуется после одной
попытки изменения (включая ошибку); отмена диалога его не расходует.
Terminal допускает несколько команд в течение минуты: срок отсчитывается при
снятии readonly на открытой вкладке terminal или при входе в неё с разрешёнными
изменениями, команды его не продлевают. Уход с вкладки/карточки terminal сразу
включает readonly. В настройках этой галочки нет. Локальный флаг не
заменяет RBAC и не ограничивает прямой доступ к существующему localhost proxy.
Подтверждение YAML/CPU/RAM, restart и удаления Pod показывает тип и точный
кластер/namespace/имя на контрастной плашке; достаточно ответа «Да» / «Нет».
У стрелок масштабирования и команд terminal отдельного подтверждения нет.
Учитываются UID/version
просмотренного объекта, серверный dry-run, запросы ресурсов, результат проверки
HPA и риск изменения QoS/rollout. Политику квот и допустимые ресурсы задаёт сервер.

Controlled Pod обслуживается через policy/v1 Eviction с UID-precondition.
При отказе PDB прямой DELETE автоматически не выполняется; создание замены не
обещается. Удаление standalone Pod — отдельное окончательное действие.
Exec перед запуском проверяет актуальный enabled/UID, но атомарного запуска по
UID существующий протокол не гарантирует. Локальный таймаут не гарантирует
завершение удалённых процессов — перед повтором проверьте результат.

Импорт вкладок ограничен 1 МБ и 100 вкладками, валидируется до изменения состояния.
Списки читаются постранично с общим бюджетом, не более 40000 объектов/32 МБ.
Старые области матрицы при ошибке отмечаются как устаревшие; Ready/waiting/terminated
учитываются в health, а не только phase. Карточки читают ресурс заново.
Метрики/списки используют общий TTL-кэш 5 с с single-flight; отсутствие nodes/proxy
безопасно оставляет часть метрик недоступной. Не выдавайте это право ради графика.

Просмотр логов Pod: по умолчанию последние 1000 строк. «full log» пытается
показать весь доступный лог до 4 МиБ / 50000 строк; при превышении галочка
снимается и предлагается скачать лог в файл. Скачивание идёт по 64 КиБ,
не собирает полный текст в RAM и атомарно заменяет файл только после успеха.
При обрыве старый файл сохраняется, временный удаляется. Чтение ограничено
300 секундами (сокетный timeout 10 сек); ротированную историю сервера оно
не восстанавливает. Обычное «Сохранить…» экспортирует показанный фрагмент.
Новые данные опрашиваются каждые 5 секунд видимости страницы независимо
от autoscrolling. Действия в тексте/поиске отключают только автопрокрутку;
включение галочки сразу показывает конец последнего полученного фрагмента.
Перенос строк выключен, доступна горизонтальная прокрутка. Консоль — literal plain
text, до 2000 блоков/500000 символов; большая одиночная строка тоже ограничена.

## Данные и секреты

Пароль сохраняется только по галочке и остаётся зашифрованным. В Windows ключ
`UserData/portable.key` защищён DPAPI текущего пользователя. Старый ключ
мигрирует атомарно при следующем запуске без смены токенов/паролей. Копирование
папки другому пользователю Windows не является способом переноса подключения:
потребуется повторный вход. На других ОС сохранён legacy portable-режим AES-GCM;
он не имеет защиты Windows DPAPI. Пароли/токены не выводятся в application audit.
Redaction-реестр ограничен TTL/ёмкостью; физическое затирание Python-строк не обещается.

Одна UserData открывается только одним штатным экземпляром (QLockFile до создания
ключа). Ошибка формата JSON/размера выдаёт контролируемую ошибку; неправильные
views восстанавливаются к безопасной вкладке. Не открывайте ту же UserData из
сторонних записывающих скриптов параллельно приложению.

Локальный `audit.jsonl` пишет intent/success/unknown с correlation ID и метаданными
цели, без raw команд/тел запросов. Ротация: 2 МБ, 3 архива. Хвост читается ограниченно
в worker. Локальный аудит доступен владельцу для изменения и не заменяет серверный.
Настройки объединяются и сохраняются в фоне; при выходе финализатор завершает
работу и сохраняет последние значения до освобождения single-instance lock.

## Снимок и откат

```powershell
.\venv\Scripts\python.exe snapshot.py
```

Новые code-only ZIP содержат код/документацию/assets и manifest SHA256; UserData,
ключи, окружения, Addons и внешние клиенты исключаются. Для восстановления кода
проверьте manifest и распакуйте ZIP в закрытую копию приложения, сохранив свою
UserData. Исходный полный снимок до редизайна находится в
`_rollback/20261111-132543-before-ide-layout/RESTORE.md`; он намеренно сохранён
и содержит старый portable-ключ и credentials. После DPAPI-миграции старому
коду нужны данные снимка: helper отклонит несовместимый откат без
`--with-user-data` до изменения файлов. Это чувствительная историческая
копия, не образец безопасного нового снимка и не файл для передачи в поддержку.

## Проверки и сборка

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
.\venv\Scripts\python.exe -m compileall -q main.py quaber tests
.\venv\Scripts\python.exe release_manifest.py
.\venv\Scripts\python.exe -m pip check
.\venv\Scripts\Activate.ps1
.\build_windows.ps1
```

Сборка проверяет Python 3.11 x64 и точные версии requirements.lock; создаёт
CycloneDX `sbom.json` и `release-manifest.json` с SHA256 артефактов. Это не
обещание бит-в-бит одинаковых результатов PyInstaller. Поставляется вся папка
build-artifacts/Quaber; UserData при обновлении сохраняйте отдельно.

До выпуска в отдельном tooling-окружении с pip-audit выполните
`audit_dependencies.ps1` с доступом к актуальной базе. В текущем окружении
pip-audit отсутствует: CVE-скан не выполнен, отсутствие уязвимостей не заявляется.
Приёмка с реальным корпоративным клиентом, PDB/RBAC/admission и длительной
нагрузкой остаётся отдельной проверкой. Локальные тесты используют временные
данные и mock API, рабочие кластеры не изменяют.


## Доработка REPORT.md

Список «Все Pod» показывает все типы владельцев в выбранном namespace;
матрица теперь включает и другие типы нагрузок. Deployment с желаемыми репликами и без
созданных Pod не скрывается. Live Details можно обновить отдельно, грязный YAML
сохраняет своё основание версии. Настроенные размеры и порядок сохраняются.
Разрешение записи сбрасывается при каждом запуске. После записи сообщение
подтверждает принятие API, а не успешное завершение rollout.

Результаты и оставшиеся задачи, включая блокировку GUI большой матрицей,
описаны в audit-2026-11-11/REPORT.md. Вывод названий кластеров теперь управляется галочкой в настройках.

## Уточнения интерфейса от 12.11.2026

- Число реплик — прежняя кнопка «Число копий». Математический пример остался
  только при снятии «Только просмотр»; подтверждения конкретных действий остаются
  обычными, а проверки UID/version/dry-run сохранены.
- YAML не подменяется при опросах. Сравнение с сервером идёт каждые 5 секунд
  видимости карточки, текст/курсор/прокрутка не меняются. При отличии появляется
  Reload; локальные правки заменяются только после согласия. Live-сведения и
  версии для обычных операций обновляются независимо от основания YAML-черновика.
- Кнопка «Обновить» из логов убрана: опрос автоматический, F5 доступен как ручной
  повтор. Вкладка команд и пункт ПКМ называются terminal.
- Вверху боковой панели — public/logo.png, значок окна — public/icon.webp.
  Эти файлы включаются в portable-сборку и code-only снимки.
- Настройки → «Названия кластеров в заголовках namespace» включает/выключает
  подписи кластеров. Имя всегда доступно в tooltip, независимо от галочки.
- В матрице Deployment расположены первыми; ниже StatefulSet, DaemonSet,
  независимые ReplicaSet/ReplicationController, Job/CronJob и отдельные Pod.
  Группы разделены жирной линией. CronJob → Job → Pod и Deployment → ReplicaSet
  → Pod связываются по UID, без дублирования Pod в промежуточных строках.
  Для новых типов контроллеров карточки доступны только для просмотра.
- Дополнительные списки читаются существующим REST через proxy. При отказе
  RBAC свежие Deployment/Pod сохраняются; по типу отмечается ошибка. Счётчик
  «Не обновлено областей/типов» и tooltip показывают причину; старые данные
  не выдаются за свежие. Никакие дополнительные права не выдаются автоматически.
- Окно повторного входа ещё уменьшено; настройка сохранения пароля сохранена.
  Статус успешной записи — короткое «Изменение принято».

  открывает точный ввод. Управление использует прежние readonly, UID/version,
  подтверждения и серверный dry-run. До загрузки данных диаграмма показывает «—».
- Кнопка «Обновить объект» повторно читает состояние Deployment и его Pod, затем
  обновляет метрики. При обычной работе это выполняется каждые 5 секунд.
  Кнопка не применяет YAML: серверные отличия по-прежнему требуют Reload.
- Изменённый YAML сохраняется кнопкой «Сохранить YAML» над редактором или Ctrl+S.
  Перед отправкой — одно подтверждение с раскрываемым diff. Кнопка «Поиск» и Ctrl+F открывают

- Заблокированные кнопки имеют серый фон в обеих темах, клик сразу показывает
  причину блокировки. Стандартные ответы диалогов переведены на русский.
- В подтверждении scale requests показываются в millicpu/Mi и относятся к
  контейнерам обычного шаблона: это не текущее потребление, не limits и не полный
  расчёт квоты с init-контейнерами/overhead/rollout surge. HPA, найденный для
  конкретного Deployment, отмечается отдельно; отказ API/RBAC не считается его
  отсутствием. Уменьшение/большое увеличение и namespace kube-* используют то же
  подтверждение «Да» / «Нет», без ввода точной цели.

Уточнение подтверждений 13.11.2026: для YAML/CPU/RAM, restart и удаления
Pod используется единое предупреждение с типом и расположением ресурса. Плашка
имеет цвет панели навигации в режиме изменений; отрицательный ответ выбран по
умолчанию, Esc отменяет действие. Diff YAML/ресурсов раскрывается в этом же окне.
Ввод точного расположения удалён также для Pod без контроллера. Математика
остаётся только при снятии readonly. Цель карточки фиксируется при открытии;
изменение цели/UID блокируется повторно перед постановкой операции в очередь и
перед её выполнением. Запросы используют сохранённые cluster ID, тип, namespace,
имя и UID; проверки версии, dry-run и PDB сохраняются.

Уточнение readonly 13.11.2026: завершение scale, YAML/ConfigMap, CPU/RAM, restart
или удаления Pod возвращает «Только просмотр» до показа результата. Это относится
к успеху, ошибке и отказу очереди; «Нет» в предупреждении разрешение сохраняет.
Одновременно выполняется только одна операция изменения на всё приложение.
Пока она идёт, повторное снятие readonly не выдаёт новое разрешение. Для terminal
действует отдельный минутный таймер без продления при вводе/командах; завершение
одной команды не блокирует следующие до истечения срока или ухода с вкладки.
После истечения срока доступа новая команда не отправляется и остаётся в поле.
Readonly у YAML всех ресурсов и ConfigMap запрещает пользовательские изменения,
сохраняя выделение, поиск, копирование и имеющиеся несохранённые черновики.

## Доработка по образцу консоли OpenShift, 13.11.2026

- Матрица запрашивается сразу после запуска. При первой загрузке Pod/Deployment
  показываются по мере чтения namespace, до завершения дополнительных списков.
  Полное завершение и ошибки по-прежнему видны в статусе обновления.
- Меню слева сворачивается кнопкой << до 56 px; >> возвращает ширину 240 px.
  Выбор сохраняется, пункты имеют векторные значки и подсказки. Настройки не имеют
  индикатора выбранной страницы; readonly/help используют общий фон панели.
- Заголовки групп матрицы — цельные полосы по ширине таблицы с названием по центру.
  Наведение не подсвечивает строку данных; подсказка объясняет сущность. Редактирование
  ячеек отключено на всём виджете, включая пустые. Недавние рестарты отмечены голубым
  квадратом с круговой стрелкой. Меню фильтров имеет чекбоксы и остаётся открытым.
- Карточка занимает всю рабочую область справа от навигации. Повторный счётчик
  реплик из верхней строки и кнопка «Обновить объект» убраны. Данные обновляются
  автоматически; время успешного чтения выводится в статусную строку.
- Управление репликами: стрелки рядом с кругом отправляют ±1 без подтверждения;
  readonly, одноразовое разрешение, UID/version и dry-run сохранены. Кнопки
  «Запланировано» нет. HPA и текущий rollout блокируют ручные стрелки.
  Во время перехода читаются свежие Pod/ReplicaSet каждую секунду, после завершения —
  раз в 5 секунд. Цвета кольца относятся к фактически прочитанным состояниям Pod.
  Обычный scale показывает один круг и переход к цели; rollout разделяет старую и
  новую ревизии по UID ReplicaSet, без определения владельца по префиксу имени.
  Запоздавший ответ чтения до записи не заменяет новое состояние карточки.
- YAML: компактная строка, «Обновить» рядом с «Сохранить YAML». При серверном
  изменении кнопка обновления синяя; текст редактора заменяется только по ней.
  Diff раскрывается двумя панелями «До»/«После», с исходными номерами строк,
  красными удалениями, зелёными добавлениями и общей вертикальной прокруткой.
- Логи: минимальные отступы, «Сохранить log…», autoscrolling включается при открытии
  вкладки и нового источника; действия пользователя в тексте/поиске по-прежнему
  отключают его. «Предыдущий запуск» — previous=true в Kubernetes Pod log API:
  предыдущий экземпляр выбранного контейнера этого же Pod, если лог ещё доступен.
- Terminal не запрашивает подтверждение команды. Проверки readonly, минутного
  срока, активной вкладки, выбранного контейнера и UID остаются. Навигация открывает
  новую карточку с её собственной identity; до завершения перехода команды запрещены.
- Первая точка графика справа, затем история заполняется влево на окне 120 точек.
  Для пустых событий, контейнеров и метрик показываются явные сообщения.

Образец проверен в локальной консоли: Deployment quota-demo/sqrt-counter, 7 → 8 → 7.
Также изучены [PodRing](https://github.com/openshift/console/blob/984a759d2795203fe094dbe3fa6db779dd8f3390/frontend/packages/console-shared/src/components/pod/PodRing.tsx),
[PodRingSet](https://github.com/openshift/console/blob/984a759d2795203fe094dbe3fa6db779dd8f3390/frontend/packages/console-shared/src/components/pod/PodRingSet.tsx)
и [правила текста кольца](https://github.com/openshift/console/blob/984a759d2795203fe094dbe3fa6db779dd8f3390/frontend/packages/console-shared/src/utils/pod-ring-utils.ts).
Desktop использует ограниченный опрос REST вместо web watch; штатные механизмы
login/exec/proxy и TLS этой доработкой не менялись.
Подробности предыдущего запуска контейнера — в [документации Kubernetes по логам](https://kubernetes.io/docs/concepts/cluster-administration/logging/#pod-and-container-logs).

Голубой квадрат со стрелкой в матрице отмечает Pod, созданный либо перезапущенный
за последние 30 минут. Время создания учитывает пересоздание Pod с новым UID,
когда счётчик рестартов контейнера ещё равен нулю. Для старых Pod учитывается
время последнего перезапуска контейнеров, включая init-контейнеры. Подсказка
сохраняет фактические Created/Restarts, поэтому эти случаи можно различить.

Рядом с фильтром рестартов находится «Режим деплоя» с обратным отсчётом на 30 минут.
Он временно возвращает работающим Pod обычный зелёный цвет, не меняя состав
таблицы и фильтры. Можно выключить его раньше; по истечении срока обычная голубая
индикация возобновляется автоматически. Режим общий для представлений; сохраняется
время окончания, поэтому перезапуск приложения не продлевает его. Старые маркеры
снимаются локально даже при выключенном автообновлении данных.

Уточнение интерфейса и стрелок реплик (13.11.2026):

- Клики по ↑/↓ меняют локальную цель. Через 5 секунд после последнего клика
  отправляется одно масштабирование до итогового значения: три ↓ означают −3,
  пять ↑ и два ↓ означают +3. Рядом с кольцом показаны цель и обратный отсчёт.
  До отправки число реплик на сервере не меняется; после завершения возвращается
  readonly. Для отдельного цикла 0 → 5 сначала дождитесь фактического нуля,
  затем снова снимите readonly и выберите пять реплик.
- Включение readonly, уход с вкладки или карточки отменяет ещё не отправленную
  цель. Во время отправки повторные изменения заблокированы. Перед записью
  проверяются UID и исходное число реплик, затем используется свежий
  resourceVersion; чужое масштабирование вызывает отказ, не перезаписывается.
- «Restart rollout» обновляет аннотацию шаблона Deployment и сразу включает
  быстрый опрос rollout. Это штатный механизм [rollout restart](https://kubernetes.io/docs/reference/labels-annotations-taints/#kubectl-kubernetes-io-restartedat).
- В матрице меняются только ширина столбца названий и высота шапки по её нижней
  границе. Ячейки Pod имеют фиксированную ширину и автоматическую высоту;
  сохранённые раньше размеры этих ячеек больше не применяются.
- Поля карточек заполняют общую сетку без растянутых пробелов. Кольцо находится
  слева над данными, как в проверенной локальной консоли OpenShift. Шапки и
  системный заголовок Windows получают цвет режима изменений; readonly имеет
  красный предупреждающий значок, на красной панели он жёлтый с белой обводкой.
  Значки настроек и помощи перерисованы векторно.
- YAML: слева «Обновить» и сообщение об изменении; справа «Поиск», затем
  «Сохранить YAML». При отсутствии серверных отличий сообщение скрыто,
  «Обновить» заблокирована. Выделение строк Pod заметно в обеих темах.
- Чекбоксы меню фильтров смещены вправо. Заголовок квот заметнее, название
  карточки — `quota: кластер / namespace`; имя ResourceQuota сохранено в подсказке.

Следующее уточнение интерфейса (13.11.2026): кнопки бокового меню возвращают
в свой раздел даже при повторном нажатии выбранного пункта. Вложенные карточки
закрываются после проверки несохранённого YAML; отмена оставляет карточку открытой.
Отступы ConfigMap согласованы с шапкой, наведение выделяет всю строку Pod в обеих
темах. «Режим деплоя» находится внизу матрицы, «Скрыть пустые» — справа сверху,
фильтр называется «Перезапущенные < 30 мин»; «Только проблемы» убран.

Кнопка «Режим администратора» включается через прежнее подтверждение примером.
По умолчанию выключена; одно изменение, минутный terminal и отложенные стрелки
сохраняют свои ограничения. Значки меню 22 px в строках 44 px, справка монохромная.
Для Pod с двумя обычными контейнерами, один из которых содержит `istio` в имени,
логи, terminal и метрики первоначально выбирают второй контейнер. Ручной выбор
сохраняется при обновлении.

В графиках доступны только 1, 5, 10 и 30 минут, по умолчанию 1 минута. Данные
сохраняются в памяти до 30 минут независимо от выбранного периода, отдельно
по UID Pod и контейнеру; расширение периода возвращает скрытые точки. Сбор идёт,
пока видна вкладка метрик. Повторное открытие того же Pod сохраняет накопленное
за текущий запуск приложения; пропуски сбора и время до его начала не заполняются.
Подключённые Metrics API/kubelet/cAdvisor дают текущие значения; серверный архив
требует отдельной системы мониторинга, например [Prometheus](https://github.com/kubernetes-sigs/metrics-server#use-cases).

В настройках колонка «Доступ» показывает проверенные эффективные права:
администратор ресурсов, редактирование, чтение или неопределённый результат.
Подсказка уточняет проверенные namespace и операции, неполные/ограниченные правила.
Используются [SelfSubjectAccessReview и SelfSubjectRulesReview](https://kubernetes.io/docs/reference/access-authn-authz/authorization/#checking-api-access),
без чтения чужих ролей и без изменений ресурсов. Имя пользователя не определяет
уровень. Кнопка администратора разрешает действия только локально; серверные права
сохраняются. HTTP 403 при изменении и Forbidden при terminal выключают этот режим.
Отказ чтения метрик или проверки прав не считается отказом на редактирование.

Ограничения администратора и новые разделы (13.11.2026):

- «Режим администратора» доступен только после подтверждения полных прав на
  ресурсы кластера через SelfSubjectAccessReview. Доступ уровня «Редактирование»
  его не разрешает. На главной странице, в Dumps/сверке и карточках/вкладках без
  видимых операций изменения кнопка недоступна; подсказка объясняет причину.
  Для ConfigMap режим включается на вкладке YAML. Перед включением и перед
  отправкой каждого изменения права проверяются заново. Неудачная проверка,
  потеря прав и серверный запрет выключают режим. Черновик YAML сохраняется.
- Курсор графика привязывается к ближайшей доступной точке по всей области
  графика; пустые измерения пропускаются.
- **Dumps** читает Deployment и CronJob выбранных активных кластеров и показывает
  каждую запись в формате скрипта: хост, namespace, тип, имя, образы контейнеров,
  ветка, кем задеплоен, версия. Несколько образов, включая init-контейнеры,
  разделяются `;`. Таблица и CSV используют одни и те же значения полей.
  Над таблицей указано число кластеров и ресурсов, в подсказке — время и ошибки.
  «Экспортировать дамп» сохраняет один CSV с видимыми строками таблицы. Формат CSV и порядок
  поиска branch/deployed by/version соответствуют [export-curl.cmd](../addons/export-curl.cmd):
  metadata → jobTemplate (CronJob) → Pod template, включая init-образы. Используются
  подключения приложения; отдельный запуск CMD/curl/login не требуется. При ошибке
  чтения неполнота отмечается в интерфейсе и подсказке. Это перечень
  Deployment/CronJob и меток, а не резервная копия всех объектов кластера.
- **Сверка версий** сопоставляет сервисы по `app.kubernetes.io/name` между
  выбранными парами «кластер / namespace». Можно сравнивать namespace одного
  или нескольких кластеров, выбирая их чекбоксами. Второй список выбирает метки
  для сравнения. Ресурсы без метки приложения учитываются отдельно. Одинаковые
  пустые значения метки во всех выбранных namespace считаются совпадением;
  пустое значение против заполненного — различием. Отсутствующий сервис и
  непрочитанные данные имеют отдельные состояния. Каждая метка имеет свой цвет:
  совпадение зелёное, различие и отсутствие сервиса — красное;
  неполные данные остаются нейтральными. Цвета адаптируются к светлой и тёмной теме.
  Столбец «Состояние» показывает результат сверки выбранных меток; подсказка
  поясняет каждое значение. Подсказка ячейки namespace показывает имена исходных ресурсов.
  Эти разделы читают данные; режим администратора для них не нужен. Снимки
  переиспользуются до 60 секунд, «Обновить» и F5 выполняют новое чтение.

Копирование и автообновление интерфейса (16.11.2026):

- В настройках хост и логин копируются через Ctrl+C после выбора ячейки или
  через пункты «Копировать хост/логин» в контекстном меню. Двойной клик открывает
  поле только для чтения, где можно выделить и скопировать часть строки.
- Границы изменяемых столбцов отмечены тонкими разделителями заголовка,
  при наведении и перетаскивании граница становится синей. Ширина, заданная
  вручную, сохраняется при обновлении таблицы в текущем сеансе.
- Поиск матрицы с подсказкой «Имя Deployment…» фильтрует имена строк нагрузок.
  Имена вложенных Pod и namespace не участвуют в этом фильтре; поиск в списках
  Pod по-прежнему доступен отдельно.
- Обзор Pod, Deployment и ConfigMap обновляет документ только при изменении
  видимых данных. Выделение текста и прокрутка сохраняются. Пока текст выделен
  или пользователь выделяет его мышью, новая версия обзора откладывается до
  снятия выделения; затем показывается последнее полученное состояние.
  Сам ресурс и сведения для YAML продолжают обновляться.

- Фильтры матрицы расположены в порядке «Кластер → Namespace → Deployment».
  Новые обнаруженные сущности автоматически включаются в существующие виды;
  ранее снятые оператором отметки сохраняются. Известные сущности сохраняются
  вместе с видом, поэтому правило действует и после перезапуска приложения.
  Высота строк учитывает перенос длинных имён жирным шрифтом.

Реплики, ресурсы и проверка изменений (16.11.2026):

- После нажатий стрелок появляется Apply с пятисекундным отсчётом и Cancel.
  Apply применяет итог сразу, Cancel отменяет ожидающее изменение и выключает
  режим администратора. Автоматическое применение после паузы сохраняется.
- В журнале есть поиск с переходами вперёд/назад и циклическим продолжением:
  Ctrl+F, Enter, F3 и Shift+F3. Поиск выключает автопрокрутку.
- «Ресурсы…» разрешены на вкладке «Метрики» открытого Deployment. Отдельного
  окна выбора контейнера нет: выбирается текущий контейнер графика, иначе первый
  без istio; при нескольких контейнерах выбор доступен внутри формы ресурсов.
  Сводная таблица показывает память в MiB, ниже доступны графики выбранного Pod.
- Изменения всегда показываются рядом в панелях «До/После», без галочки.
  Окно сравнения показывает таймер доступа и позволяет его продлить. Пока окно
  открыто, обычные клики не сбрасывают таймер. При истечении применение блокируется,
  окно остаётся открытым; YAML-черновик сохраняется, в том числе при отмене применения.
- Перед записью YAML и ресурсов выполняется серверный PUT с dryRun=All;
  масштабирование и restart rollout также проходят серверный dry-run. Проверяются
  выбранная цель, UID и resourceVersion; отказ проверки не приводит к записи.
- Локальная запись clusters.json повторяет атомарную замену при временном
  PermissionError; чтение и запись подключений синхронизированы. При постоянном
  отказе старый файл сохраняется и показывается понятная ошибка сохранения.
